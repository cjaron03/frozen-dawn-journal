What it actually is

Frozen Dawn does one thing to your world: it takes the sun away, slowly, and never gives it back.

Not as a cutscene. Not as a scripted event on day forty. The whole collapse is a single number between 0 and 1, the fraction of the world's lifespan that has already burned, and every visible symptom is read off that one number. The sun's size. The colour of the sky. How cold it is where you are standing. How long daylight lasts. Whether water can still exist as a liquid.

That design decision is the whole mod. It means there is no state to desync, no timer to drift, nothing to save except the day counter. Load a world on day 61 and the sky is already black, because black is simply what the function returns at 0.61.

It also means I can show you the entire thing in a slider.

Six arrays and a list of boundaries. That is the whole collapse.

Every value the slider showed you is one row of this table, read at one position. There is no simulation state behind it, no accumulator, no drift. Given the same day, it returns the same world.

The six arrays, PhaseManager.javaJava
// PhaseManager.java private static final float[] PHASE_BOUNDS = {0.0f, 0.05f, 0.12f, 0.22f, 0.34f, 0.46f, 0.60f, 1.00f}; private static final float[] SUN_DISTANCE = {1.0f, 0.35f, 0.12f, 0.06f, 0.04f, 0.03f, 0.02f, 0.0f}; private static final float[] TEMP_OFFSET = { 0f, 0f, -10f, -25f, -45f, -70f, -120f, -273f}; private static final float[] SUN_BRIGHTNESS = {1.0f, 1.0f, 0.9f, 0.7f, 0.45f, 0.2f, 0.05f, 0.0f}; private static final float[] SKY_LIGHT = {1.0f, 1.0f, 1.0f, 0.85f, 0.6f, 0.3f, 0.05f, 0.01f}; private static final float[] DAY_LENGTH = {1.0f, 1.0f, 0.95f, 0.8f, 0.6f, 0.4f, 0.2f, 0.0f};

The boundaries are deliberately uneven. Phase 0 is five percent of the world's life, phase 6 is forty. The early phases are short because they are supposed to feel like weather. The last one is long because it is supposed to feel like it will never end.

Look at what SUN_DISTANCE does between the first two stops: 1.0 down to 0.35 across five percent of the run. That is the fastest change in the entire mod, and it happens before most players have a bed. By the time anyone notices the sun is smaller, the interesting part of the curve is already behind them.

How a value is found
interpolate(), the fourteen lines everything callsJava
private static float interpolate(float[] values, int currentDay, int totalDays) { float progress = getProgress(currentDay, totalDays); for (int i = 1; i < PHASE_BOUNDS.length; i++) { if (progress <= PHASE_BOUNDS[i]) { float segStart = PHASE_BOUNDS[i - 1]; float segEnd = PHASE_BOUNDS[i]; float segProgress = (progress - segStart) / (segEnd - segStart); return Mth.lerp(segProgress, values[i - 1], values[i]); } } return values[values.length - 1]; }

Fourteen lines, called by everything. The sky renderer calls it. The freezer calls it. The heads-up display calls it. Nothing owns the collapse, which is why nothing can get out of step with it.

A number going down is not a feature. The feature is what the world does about it.

Each phase unlocks a specific set of block transformations, and each one escalates the number of checks per player per tick. Phase 2 does one pass. Phase 4 does five times that. The world does not just get colder, it gets colder faster.

And your heat shrinks with it

Phase 5 does not only raise the bill, it quietly shortens your reach. Every lit thermal heater checks one line before deciding how far it warms, and from phase 5 onward a heater with no roof over it keeps only sixty percent of its radius, rounded down.

Radius in blocks, bare / with capacitor. Warmth in degrees, flat anywhere inside the radius.

That comment is the whole balance decision in one line. A diamond heater standing in the open still out-reaches a plain one under a roof, eight blocks against seven, so the top tier never turns into a downgrade and a roof never turns into a requirement. Shelter only makes what you already built go further.

Campfires, furnaces and lava never take the cut at all. They sit on a different code path that is handed no phase at all, so they keep every block of their radius and simply stop mattering instead: a soul campfire is worth twenty eight degrees against an ambient minus seventy.

One phase later, a roof stops being enough by itself. What a room has to hold in is no longer heat, and the question changes from how warm you are to whether you can breathe at all. That is the next section.

Depth is the answer, and it is also a curve

The one honest escape is downward. Temperature gets a depth modifier that is its own ladder, from minus ten at build height to plus eighty at bedrock. Deep enough and the surface reading stops mattering, which is exactly why phase 6 eventually reaches down and takes that away too.

Every other phase takes something away by adding something: fog, snow, dark. The last one takes things away by removing the air they were in.

Phase 6 covers the final forty percent of the world's life and it is the only part of the collapse with internal stages of its own. They are constants, not a separate system, so the same single number still drives everything.

The phase 6 thresholds and the stage enumJava
public static final float PHASE6_START = 0.60f; public static final float PHASE6_MID_START = 0.72f; public static final float PHASE6_VACUUM_START = 0.85f; public static final float PHASE6_END = 1.00f; public enum Phase6Stage { INACTIVE, EARLY, MID, VACUUM }

Frozen atmosphere

Below minus one fifty, with direct sky access, the air itself starts settling out as a block. It is the only mechanic in the mod that is genuinely reversible, and it reverses for a reason: if a player builds a heat source, the deposits around it sublimate away. The world you are given back is exactly as big as the warmth you can hold.

The detail I am most attached to

The block freezer keeps escalating inside phase 6 even after the surface is finished. Past 0.65 it starts a second sublimation pass, and past 0.75 it adds another ten percent on top of every remaining conversion chance. There is nothing left to convert by then. It runs anyway, because a world that stops changing when it is finished feels finished, and this one is supposed to feel like it is still going somewhere without you.

You walk two thousand blocks east on day seventy and the grass is green.

This is the bug that gave the chapter its name, and it is not really a bug. Minecraft generates terrain on demand. Every ambient system in Frozen Dawn, the freezer, the snow, the vegetation decay, only runs inside a 64 block radius of a player and only gets a few hundred block checks per tick. Terrain that has never been loaded has never been cold. The apocalypse had been happening, precisely and beautifully, only in the places someone had already stood.

So it needed a way to give a brand new chunk a past.

The class javadoc, ChunkCatchUpManager.javaJava
/** * Applies coarse apocalypse epochs to naturally loaded chunks. * * This is not a missed-random-tick simulator. It makes stale/new chunks * visually believable for the current phase while staying inside a * bounded server budget. */

That second sentence is the entire design. Replaying two months of missed ticks is impossible and also pointless. Nobody saw those ticks. What has to be true is only that the chunk looks like somewhere the last seventy days happened to, and that producing it does not stall the server.

Seven passes, and the order is load-bearing

A chunk is not transformed in one go. It is walked through seven passes, each with its own cursor, and the work can stop between any two of them and resume on a later tick. The order is not arbitrary: trees have to come out before snow is reconciled, or snow lands on branches that are about to be deleted and then floats.

TREE_CLEARStrip dead canopy, 96 blocks deep. First, because everything below depends on it.
DETACHED_SNOWRemove snow that was resting on something the previous pass just took away.
SURFACEThe top face of every column: freeze, convert, kill.
SURFACE_COLUMN48 blocks down from the surface. 12,288 positions per chunk.
VOLUME_SAMPLE768 sampled positions in the deep volume. Sampled, not exhaustive, on purpose.
COAL_SAMPLECoal ore crystallization, its own pass because its rules differ.
ATMOSPHEREFrozen atmosphere deposits, last, once the world beneath them is settled.
A version number is a promise
TRANSFORM_VERSION and needsCatchUp()Java
public static final int TRANSFORM_VERSION = 4; public boolean needsCatchUp(int chunkX, int chunkZ, int transformVersion, int targetDay) { Record record = get(chunkX, chunkZ); return record == null || !record.complete || record.transformVersion < transformVersion || record.targetDay < targetDay; }

Every chunk stores the version of the transform it received and the day it was brought up to. Change the rules, bump the number, and every chunk in every existing save quietly re-qualifies for catch-up the next time it loads. It has been bumped four times. That single integer is the reason I could keep changing what phase 4 means without breaking anybody's world.

The one deliberate exception: chunks inside a protected ORSA structure are marked complete without being transformed at all. The sanctuaries are supposed to be the places the apocalypse did not reach, and the cheapest way to guarantee that is to make the catch-up system agree.

And then the silence

Forty-one days with no commits, starting five days after the chunk loader's rewrite. I would like to say it was a planned break. It was not. I had just spent a week rewriting two thirds of the hardest file in the project because the first version stalled the server, it was finally correct, and I could not make myself open the editor again.

The thing that eventually brought me back was a bug report about snow floating where a tree used to be. Not a grand plan, not a new feature. A one file fix, 136 lines, in the same class I had walked away from.

The mod is about a world that keeps getting colder whether or not anyone is there to watch. I did not notice until I read my own commit history back that I had built the system that handles exactly that, and then tested it on myself.
